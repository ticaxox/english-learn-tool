# 安全与隐私

- 事实基线：`caa731c`；容器/CI 安全基线对应 `a5bf49b` / run `39801657963`
- 当前安全状态：基础配置、日志、健康检查、敏感信息扫描和容器运行边界已实现；身份与业务权限尚未实现
- 目标产品安全基线：组织内私有部署，管理员不得读取成员答案、草稿和教练对话

## 1. 当前已实现

### 配置校验

`backend/app/core/config.py` 当前会校验：

- `DATABASE_URL` 必须使用 `postgresql+asyncpg://`。
- `REDIS_URL` 必须使用 `redis://` 或 `rediss://`。
- `JWT_SECRET`、`REFRESH_TOKEN_PEPPER`、`SECRET_ENCRYPTION_KEY` 至少 32 个字符。
- 应用和前端 Base URL 必须是绝对 HTTP(S) URL，且不能带用户名或密码。
- `APP_TIMEZONE` 必须是有效 IANA 时区。
- `CORS_ORIGINS` 至少有一个合法来源，不能包含路径、查询或片段。
- `LOG_LEVEL` 必须是标准日志级别。

### Request ID 与日志

- 接收合法的 `X-Request-ID`，否则生成新 ID。
- 所有响应回写 `X-Request-ID`。
- 访问日志记录方法、路径、状态码、耗时和 Request ID。
- 当前日志不主动记录请求体、密码、令牌或密钥。
- 未处理异常返回统一 500 错误，不向客户端输出内部堆栈。

### 健康检查

- `/health/live` 不访问依赖。
- `/health/ready` 只返回组件状态、延迟和异常类型。
- 错误详情不返回数据库连接串、密钥或完整异常消息。

### Secret 边界

- `.env.example` 只含占位值，不含可用凭据。
- `.env`、真实 API Key、生产连接串和成员数据不得提交 Git。
- 前端不将 Access Token 写入 `localStorage` 或 `sessionStorage`；当前只在内存保存。
- 现有仓库资料中没有业务真实用户数据或 AI provider。

### 容器与 CI 安全基线

`a5bf49b` 的 GitHub Actions run `39801657963` 第 2 次尝试已经验证：

- Gitleaks 扫描完整 Git 历史，未发现已提交密钥。
- API、worker、scheduler、frontend 和 reverse proxy 以 UID/GID `10001` 非 root 运行。
- 应用容器启用只读根文件系统、`tmpfs /tmp`、`cap_drop: ALL` 和 `no-new-privileges`。
- PostgreSQL 与 Redis 不发布宿主端口；默认只有反向代理绑定 `127.0.0.1:8080`。
- Compose 使用一次性迁移容器先于应用启动，迁移到 `20261022_0001`。
- 反向代理的基础健康与 API 路由通过，但尚不代表业务授权、TLS 或公网安全已验证。

## 2. 当前缺口

以下能力尚不存在，因此不能声称安全闭环已完成：

- 后端登录、JWT、Refresh Token 轮换、CSRF 和限流。
- 角色权限与资源所有权校验。
- 最后管理员保护。
- 审计事件和业务日志脱敏。
- API Key 加密存储、模型 provider SSRF 防护和 AI 调用额度。
- 上传、导入、导出与恶意文件防护。
- 教练 prompt injection 防护和受控 action 撤销。
- 管理员隐私边界集成测试。
- GHCR 发布镜像供应链、云主机加固、域名/TLS、公网入口、限流和 WAF/边缘防护。
- 生产数据库备份恢复、密钥轮换和灾备演练；现有备份/回滚脚本尚未做生产恢复验证。

## 3. 目标权限边界

| 数据 | 成员本人 | 组织管理员 |
|---|---|---|
| 本人账号状态与学习档案 | 可读/可改 | 可读聚合信息 |
| 私有词书正文 | 可读 | **不可读** |
| 答题正文、作文、翻译 | 可读本人提交 | **不可读** |
| 未提交草稿 | 可读/可续做 | **不可读** |
| AI 教练标题和消息 | 可读本人对话 | **不可读** |
| 聚合学习时长、完成率、用量 | 可读本人 | 可读组织聚合 |
| 最后管理员保护 | 不适用 | 必须强制执行 |

前端隐藏按钮或路由守卫不等于授权；后端服务层必须再次校验。

## 4. 身份与安全会话目标

- 用户名大小写不敏感唯一；密码使用 Argon2id。
- Access Token 15 分钟，仅保存在内存。
- Refresh Token 30 天、随机、数据库只存哈希，使用 `HttpOnly` Cookie 并轮换。
- 检测 Refresh Token family 重放时撤销整个 family。
- Cookie 写请求校验 `Origin` 与双提交 CSRF Token。
- 登录失败统一提示，防止用户名枚举。
- 管理员重置密码、停用或删除用户时撤销该用户刷新令牌。
- 管理员不能删除、停用或降级最后一个启用管理员。

## 5. AI 与上传安全目标

- API Key 使用服务端认证加密保存，接口仅返回掩码。
- 主密钥只来自环境变量或 KMS，不进入数据库备份或日志。
- Base URL 必须校验协议和主机，阻止云元数据地址及非预期内网访问。
- 用户输入、上传词书和模型输出均视为不可信数据。
- 结构化响应必须经过 Pydantic 和业务校验后才能保存或展示。
- 模型 Markdown 不得直接作为未净化 HTML 注入。
- 上传使用随机文件名，限制大小、行数、解析时间和解压后大小。
- 导出下载必须短期授权，不能使用可枚举公开路径。
- 题目提交前不得返回正确答案、解析或参考内容。

## 6. 日志与审计目标

建议记录：

- `timestamp`
- `level`
- `request_id`
- `user_id`（仅在必要时）
- `route`
- `method`
- `status_code`
- `latency_ms`
- `error_code`
- `job_id`

禁止记录：

- 密码、明文令牌、API Key、加密主密钥。
- 完整答题正文、作文、翻译答案。
- 教练对话全文。
- 完整上传文件内容。
- 数据库连接串和生产凭据。

管理员操作和 AI 自动写入必须进入审计记录，但不保存隐私正文。

## 7. 文档与提交物安全

- 不复制 Agent 工作区中的服务器、账号或凭据接入资料进入仓库。
- 截图、视频和日志必须使用合成组织、合成成员和合成学习数据。
- 提交前不仅检查工作树，还要检查 Git 历史、构建上下文和镜像层。
- 真实部署账号、评审账号和密码只通过受控渠道交付。
- 在认证、权限、AI Key 和数据隔离测试通过前，安全状态保持“部分实现”。
