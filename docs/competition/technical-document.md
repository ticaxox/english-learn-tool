# Grimoire｜比赛技术文档

- 版本：2026-11-18（对应 `main` @ `1cea3ff` / `v0.1.7`）
- 产品：个人 AI 英语学习空间
- 主题：万圣节昼夜双态；角色 Hob

## 1. 产品是什么

Grimoire 把一条完整的英语学习闭环做进一个个人应用：

词书 → FSRS 记忆训练 → AI 练习 → AI 教练 → 每日闯关，外加经验、等级、灯油、连续天数、徽章与周报。

它不是题库拼接：每日计划、到期复习、出题、判分、教练动作、闯关顺序都由服务端根据真实学习状态生成，浏览器只呈现。

## 2. 技术架构

```text
Vue 3.5 + TS + Vite 8 + Pinia
        │  Bearer + CSRF
        ▼
FastAPI 模块化单体（117 条 API 路径）
        │
        ├── PostgreSQL 16（59 张表，40 个迁移）
        ├── Redis 7（ARQ 队列、并发锁）
        ├── ARQ worker（AI / 词书 / 练习池）
        ├── ARQ scheduler（每日计划 / 通知 / 超时回收）
        └── 私有文件卷（词书、教练附件）

AI：OpenAI 兼容网关（chat / embedding），BYOK，Key 加密入库
RAG：题号感知分块 → 可选 embedding → 线性检索
```

设计取舍：

- **模块化单体**：领域边界清楚（`app/services/*`），但一次部署、一套事务，适合个人产品。
- **服务端唯一真相**：FSRS 调度、判分、额度、队列都在服务端；前端不持久化学习状态。
- **异步优先**：所有 AI 与导入任务都有持久任务记录，`202` 只代表已接收。

## 3. 记忆训练（FSRS）

- 使用 `fsrs==6.3.2`，只在服务端计算。
- 两档评分（again / good），关闭 fuzz，保证同一输入得到同一调度，便于测试与复盘。
- 每次答题写 `memory_events`（幂等），状态落在 `user_word_states`；支持掌握、恢复与进度重置。
- 三种模块：翻卡、选择、拼写（填空），同一张卡可在不同模块间复用。

## 4. AI 平台

### 4.1 持久任务

`ai_jobs` 保存任务类型、提示词快照、幂等键与请求哈希、provider、终态与错误码。六类任务：

| 类型 | 说明 |
|---|---|
| `practice_generation` | 生成练习题目 |
| `subjective_grading` | 主观题评分 |
| `coach_reply` | 教练回复 |
| `conversation_turn` | 对话型练习一轮 |
| `challenge_plan` | 每日闯关编排 |
| `json_repair` | 输出修复 |

### 4.2 供应商与容错

- OpenAI 兼容：`/chat/completions`、`/models`、`/embeddings`。
- 结构化输出优先 `json_schema`，上游不支持时降级 `json_object`；每个任务最多一次 JSON 修复。
- provider 按优先级降级，单 provider 最多 2 次重试；URL 校验阻止元数据与私有网段。
- 失败码细分到超时、网络、鉴权、URL 拦截、输出非法、任务超时/回收。

### 4.3 额度与并发

- 按任务计数：教练 100 / 出题 20 / 主观评分 50（每日），可按用户覆盖或设为不限。
- 账本 reserve → consume / release，`(job_id, quota_item)` 唯一。
- 每用户同时最多 2 个 AI 任务，Redis Lua 计数。

### 4.4 BYOK

每个学习者只能使用自己配置的 provider（`ai_providers.owner_id`）。这既降低运营成本，也让额度与密钥边界清晰；管理员 provider 只服务管理员自己。

## 5. RAG 与知识库

- 书架模型：公共真题架（按难度）、个人架；检索只读该学习者可读的书架。
- 分块：题号感知，900 字符、重叠 120、单文档最多 400 块。
- 向量：可选 embedding，存 `knowledge_chunks.embedding`（Postgres 数组）；没有 pgvector。
- 检索：对候选 chunk 逐条打分，`0.6·max(关键词, 余弦) + 0.4·min(关键词, 余弦)`，阈值 0.12，最多 6 条，带出处。
- 消费方：练习生成引用 3 条片段；教练 `search_knowledge` 工具带出处回答。

**边界**：线性扫描适合千级 chunk；万级需要 pgvector 与 ANN。文档如实标注这一限制。

## 6. 教练

- 长期会话、游标消息、附件、记忆快照、持久 SSE 事件日志。
- 8 个受控动作：调整计划、检索/列出/阅读知识、开始练习、启用词书、生成练习、标记复习重点。
- 每个动作有 before/after 回执，24 小时内可撤销；教练不能直接改数据库。

## 7. 每日闯关与游戏化

- 服务端准备上下文，AI 只编排顺序与文案；节点类型受白名单约束。
- 每人每天一张图，当日锁定；开始、完成与 BOSS 提交都幂等。
- 等级曲线 `120 × L^1.35`，称号余烬→火舌→熔炉→锻铁→淬火；23 枚徽章；3 条每日任务；周报含 XP 曲线、活跃天数、词态雷达与周目标。

## 8. 前端与设计

- Vue 3 + TypeScript + Vite，路由全部静态加载；唯一 fetch 封装负责鉴权、CSRF、401 刷新与错误规整。
- 后台字段映射集中在 `contract-adapter.ts`，视图只吃类型化模型。
- 万圣节素材：书本、卡框、角色、南瓜、徽章、蜡烛，全部昼夜双绘；`ArtImage` 同格叠图，520ms 交叉淡出。
- 换肤不是滤镜：昼夜是两次独立生成，夜间另有 262 条覆盖规则处理文字与非素材区域。

## 9. 安全

- Argon2id；JWT 15 分钟；Refresh Cookie 30 天、哈希存储、轮换、15 秒复用宽限。
- CSRF 双提交；**2026-11-18 起 Origin 校验关闭、CORS 反射任意来源**，写请求只剩 CSRF 防线（已知风险，公开部署前需决策）。
- AI Key AES-GCM 加密；SSRF 防护；容器非 root、只读根文件系统、`cap_drop: ALL`。
- CSP 与安全头在 nginx 与后端中间件同时输出；gitleaks 扫描历史。

## 11. 已知限制

1. RAG 为线性扫描，规模上限约千级 chunk。
2. AI 依赖第三方网关，历史失败率约 59%，主要是超时。
3. 夜间样式是覆盖规则，不是令牌翻面。
4. 后端测试与 40 条迁移尚未在真实库上完整重跑。
5. LICENSE、1080p 演示视频与稳定 HTTPS 仍缺。
